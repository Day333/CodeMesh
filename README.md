# CodeMesh

CodeMesh 是一个仅面向 Windows 的本地工作台，用来组织项目文件夹、多个 VS Code 窗口、终端和常用目录。

## 功能

- 按项目显示已打开的 VS Code 窗口，可将窗口手动关联项目并标记为“查看”“Claude Code”或“其他”。在工作区点击“镶嵌”，可将完整桌面版 VS Code 对齐到面板，与内置终端并排操作；原有插件和 SSH 会话仍在 VS Code 中运行。也可点“同屏”，将两个原生窗口并排。
- 点击左上角“工作台”，可展开或收起左侧项目与收藏列表。
- CodeMesh 内置真正可输入和保存的本地文本编辑器，可同时打开多个文件；工作区支持单屏、左右和上下分屏，编辑器与终端可任意组合。
- 一键为项目或当前目录打开新的 VS Code 窗口。
- 独立终端列表支持新建时填写名称、关联项目，之后也可随时改名和调整关联。关闭工作区面板只隐藏终端；只有从列表点击删除才结束会话。支持配色、字体和字号；下次启动恢复终端条目及目录，但启动新的 shell。
- 收藏常用文件夹，在应用内浏览、筛选、编辑 UTF-8 文本文件；旁边的外链按钮仍可用系统默认程序打开文件。
- 项目、收藏、标签和外观设置仅保存在本机，不同步到公开仓库。

## 使用

从 Windows 开始菜单打开 CodeMesh，点击“添加项目”选择常用项目目录。点击文件浏览区中的文本文件，就能在上方工作区直接编辑；`Ctrl+S` 保存，未保存时标签显示圆点。先点目标面板，再点文件或终端列表条目，可将不同文件、终端左右或上下分屏。终端列表里先填写名称、选择项目，再点 PowerShell 或 cmd 新建；列表中的名称与项目之后仍可修改。面板右上角的 X 仅关闭该面板的显示，终端继续运行；要真正结束并移除终端，点击列表条目中的删除按钮。项目卡片可启动 VS Code 新窗口。需要 Claude Code 插件时，可在工作区点“镶嵌”将真实 VS Code 对齐到左侧面板，终端显示在右侧；退出工作区或关闭 CodeMesh 后，VS Code 恢复为独立窗口。此功能需要至少约 1450×700 的屏幕工作区。也可点“同屏”使用两个独立窗口。未选择项目或文件夹时，新终端使用当前浏览目录或用户目录。

## 开发

要求：Windows 10 1809 或更新版本、Node.js 22 以上、npm、VS Code。`node-pty` 使用随包提供的 Windows x64 预编译模块，通常不需要额外安装 C++ 构建工具。

```powershell
npm ci
npm run dev
```

检查与打包：

```powershell
npm test
npm run build
npm run dist
```

安装包生成在 `release/`。VS Code 会从常见安装目录或 `PATH` 中自动查找；如果使用自定义安装位置，请将其 `bin` 目录加入 `PATH`。

## 本地数据与限制

设置写在 Electron 的 `app.getPath('userData')/state.json`。终端名称、关联项目和初始目录会保存；终端输出与命令历史不会保存到该文件。关闭 CodeMesh 时会结束 shell，下次打开时根据保存的终端条目启动新 shell。修改运行中终端的项目关联只改变列表归类，不改变 shell 当前目录。现有 VS Code 窗口通过 Windows 窗口信息识别，标题无法唯一对应文件夹时会显示“未关联”，可手动选择项目。窗口标题发生变化后，之前针对该标题的标签可能需要重新设置；同名窗口可分别关联，但这些临时关联不会跨应用重启恢复。

PowerShell 美化主题如果使用 Nerd Font 图标，请在系统中安装 MesloLGM Nerd Font Mono（或在设置中填写你安装的 Nerd Font 字体名）。CodeMesh 现在默认优先使用该字体，并会把旧版默认 Cascadia 字体设置自动迁移；手动指定过的字体不会覆盖。若仍出现方框，先确认设置里的字体名称和系统安装的字体一致，然后重新打开终端标签。

CodeMesh 不读取 Claude Code 插件内容。“镶嵌”通过定位原生 VS Code 顶层窗口实现视觉上的面板显示，并非把 VS Code 进程变为 Electron 的子窗口；其他应用窗口或系统对话框仍可能盖在其上方。CodeMesh 内的编辑器不是完整 VS Code：VS Code 扩展、远程 SSH 工作区和调试器仍在原生 VS Code 窗口中运行。内置编辑器仅支持已添加项目或收藏目录下不超过 2 MB 的 UTF-8 文本文件；二进制、大文件、其他编码请用 VS Code。保存前检查磁盘文件是否已被其他程序修改，若发生冲突会拒绝覆盖。未保存修改关闭标签时会提示。第一版不提供文件复制、移动或删除。尚未配置代码签名，因此本地安装包可能显示 Windows 发布者提示。

## 技术结构

Electron 主进程负责 Windows 窗口 API、文件系统和 `node-pty` 会话；React 界面只通过受限的 preload API 调用这些功能。终端使用 xterm.js 显示。`node_modules/`、构建产物、本机数据和 `.env` 文件不纳入 Git。
